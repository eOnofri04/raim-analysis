# Quickstart — raim-analysis

The short version. `README.md` has the detail; this page is for getting the paper's numbers out of this repository without first understanding how it is built.

## What this is, in a paragraph

RAIM asks whether a panel of ten cheap open-weight language models, used as hallucination judges and combined by a small learned aggregator, can stand in for an expensive frontier judge — and, more usefully, *when* it can.
Its companion, [`raim-verdicts`](https://github.com/eOnofri04/raim-verdicts), ran those judges and recorded what each said about each item.
This repository turns those recordings into every number, table and figure in the paper.

**Everything here is reproducible.** No GPU, no network, no API keys: the judges' verdicts are committed alongside the code, and the whole chain from them to the paper is deterministic at `seed=0`.

## Reproducing the paper

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt       # plus pdflatex for the figures, pdftoppm for figcheck (README.md, Installation)
cd scripts

make verify   PY=../.venv/bin/python3   # seconds: is the data intact, and which release is it?
make check    PY=../.venv/bin/python3   # 3 to 10 minutes: the tables and reports, regenerated into a scratch tree and diffed
make figcheck PY=../.venv/bin/python3   # under a minute: the figures, compared by pixel
```

`tables/` and `figures/` are shipped as the paper used them, and both checks compare against them without writing anything; they exit non-zero if anything moved.
The scratch trees go to the system's temporary directory (`mktemp -d`, so `TMPDIR` moves them), and are removed when the check ends.
`make tables` and `make figures` rebuild the same artefacts in place, overwriting the shipped copies, so run them after the checks rather than before: a check run afterwards would only compare the regeneration with itself.

## What lives where

```
verdicts/        what the judges said. Read-only, about 5 MB.
derived/         what we computed from it: intervals, aggregation ladders, transfer.
raim_lib/        the method: the stacker, the interval convention, verdict loading.
scripts/         the generators, and the tables and figures they write.
```

Nothing in this repository writes to `verdicts/`, and because the two data directories are different trees that is structurally true rather than a rule someone has to remember.

## Answering "where does this number come from?"

Start at the table: every generated table names its generator on line 1.

```
% AUTO-GENERATED by paper_tables.py in scripts/ -- do not edit by hand; regenerate with `make tables`.
```

`paper_tables.py` holds the dataset registry and the main tables; `raim_lib/weighting.py` holds the aggregator itself.
The decision rule — Cohen's κ, paired cluster bootstrap over `row_id` clusters at B = 2000, a win being a significant gain over the cross-validated best single judge — is computed by `weighted.py` on that aggregator, and every table reads it from the JSON that writes.
Published reference values set beside ours are hand-transcribed; `scripts/provenance/PUBLISHED_REFERENCE_VALUES.md` says where each is printed.

Numbers quoted in the text rather than in a table are in the derived JSONs of that section's generator; the headline ones, which aggregate over datasets, are printed by one command, each beside the file and key it is read from:

```bash
make numbers PY=../.venv/bin/python3   # read-only; seconds
```

`README.md`, under the "Numbers in the text" and "Other commands" sections, has the rest.

To rebuild the intermediate results rather than trust the shipped ones:

```bash
make derive      PY=../.venv/bin/python3   # rewrite derived/ from the verdicts, in twenty minutes to an hour
make derivecheck PY=../.venv/bin/python3   # the same into a scratch tree, diffed against derived/; non-zero on any change
```

Its scratch tree is kept, and named, only when the comparison fails, so that `make derivediff` can re-read it without re-deriving.
It compares floats to a tolerance (`THRESHOLD`, default `1e-8`), because the last bits of the fits depend on the machine's BLAS; integers, strings and key sets are still compared exactly.

## Which measurements am I looking at?

`make verify` prints a release digest — a single string naming the exact set of verdict files this was built from, plus the digest of the join index they are keyed against — and re-hashes every mirrored file, so a truncated copy says so rather than producing quietly incomplete results.

## Where the data came from

[`raim-verdicts`](https://github.com/eOnofri04/raim-verdicts) produced it, and `NOTICE` records the terms of the eight benchmarks it was measured on.
No benchmark content is redistributed here: a verdict record carries identifiers, labels and our own models' answers, and no question, document or candidate text.
